# Safety and Security Reporting

This repository publishes governance guidance and templates rather than executable production software. Reports may still involve unsafe guidance, privacy exposure, malicious examples, broken provenance, or a repository/security configuration issue.

## Public reports

Use a GitHub issue for a non-sensitive documentation defect, broken link, ambiguous safeguard, or public configuration concern. Describe the affected file, consequence, and a safe reproduction or correction.

## Sensitive reports

Do not open a public issue containing:

- credentials, personal data, confidential or classified information;
- active abuse, contraband, or identifying victim details;
- an exploit that would create material risk before correction; or
- private correspondence or material without publication authority.

For a sensitive repository-security report, use GitHub's private security-advisory channel when available. Otherwise contact the repository owner privately through the verified GitHub profile and provide only the minimum information needed to establish a protected follow-up channel.

## Response priorities

Maintainers should acknowledge a credible sensitive report promptly, contain public exposure, preserve necessary evidence without expanding access, identify an accountable incident owner, and publish a safe correction summary when doing so will not create further harm.

This project does not operate an emergency service. If there is imminent danger, contact the appropriate local emergency or protective service.
